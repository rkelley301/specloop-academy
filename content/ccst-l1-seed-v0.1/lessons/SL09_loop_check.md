# SL09 — Loop checks and commissioning evidence
> **DRAFT — TECHNICAL REVIEW REQUIRED.** This lesson is original educational draft content and has not been technically validated. **Objective:** Describe a point-to-point loop check and the evidence it should produce.

## Audio script

A loop check confirms that a field measurement or command travels through the intended path and is represented correctly at the destination. It is one part of commissioning and startup work, performed under the project’s approved plan.

[PAUSE 3 SECONDS]

For a measurement loop, the team may verify the field device, wiring, input channel, tag, range, units, alarm behavior, and display. For an output loop, the team may verify the command path and the expected response at the final element. The exact scope depends on the loop and the approved test procedure.

[PAUSE 3 SECONDS]

The evidence matters. Record the loop or tag identification, test point or stimulus, expected result, observed result, pass/fail status, date, people involved, and any exception or correction required by the project form.

[PAUSE 3 SECONDS]

A loop check is not a substitute for every functional, safety, or performance test. It confirms only what the procedure says it confirms. If a step is skipped or a result differs, document it and route it through the project’s resolution process.

[PAUSE 3 SECONDS]

Before testing, confirm the drawing revision, test boundaries, process state, and required approvals. Never introduce a test signal or actuate equipment without the approved coordination and safeguards.

## Recall check
1. What is the basic purpose of a loop check?
2. Name three items that make a loop-check record useful.
3. Does passing a loop check prove every function is correct?

## Scenario
A loop check passes at the input channel, but the operator display shows the wrong units. What should be documented and investigated?

## Answer key
1. Confirm the intended signal path and representation within the scope of the approved procedure.
2. Examples: tag, test point, expected and observed values, result, date, participants, exceptions.
3. No; it verifies only the scope of the test procedure.

**Scenario answer:** Record the passed measurement and the unit mismatch as separate observations. Review configured scaling, units, tag mapping, display configuration, and project records.
